# Acquisition-cohort review

Author: Jason Stys. This panel supports analysts reviewing synthetic game retention without mixing acquisition filters or treating immature windows as failures.

`GET /api/cohort-review?start=2026-08-01&end=2026-08-08&platform=pc&version=1.4.0&as_of=2026-08-08` accepts optional inclusive UTC cohort dates, one pc/console/mobile acquisition platform, a bounded semantic version and an as-known-at date. Invalid/reversed dates, injection-shaped filters or a date beyond the observed receipt watermark return422. Omitted filters include all cohorts; empty warehouses return zero totals/empty rows without invented dates.

Within one read transaction, the service first excludes events received after the cutoff (UTC calendar day, inclusive), then selects each player's earliest visible event using event time/event ID tie-breaking. Its date, platform and version define the acquisition cohort. Later cross-platform or changed-version activity counts for those members; selecting a filter never redefines “first seen” as first matching event. Earlier-than-cutoff late arrivals remain included and labelled, while later receipts do not appear retroactively in that snapshot. This uses the database's currently retained accepted data; it is not a complete event-delivery or historical database-revision archive.

Exact-day D0/D1/D7 retention uses distinct members observed on that exact UTC day. A window is mature only when its target date is at/before the cutoff. Rates divide retained members by mature members; zero mature denominator gives null and “Not yet observable.” Member/censored counts stay explicit. The receipt watermark indicates observed data, not whether absent events truly never occurred. Source quarantine remains excluded; no raw personal identifiers are added.

`src/telemetry_platform/cohorts.py` owns bound SQL and transactional totals/retention; `api.py` validates the HTTP boundary. `web/src/CohortReview.tsx` provides labelled filters, a keyboard-focusable/named scroll region, errors, no-match state and the evidence table; `types.ts` holds the shared wire contract and `api.ts` URL-encodes filters. Existing dashboard panels retain global scope. `tests/test_cohorts.py` uses independent six-event examples for acquisition changes, late hindsight, exact maturity/denominators, rollback after invalid requests, empty data, hostile filters and UTC behavior. Component tests and actual API/browser journeys cover filter submission, null versus zero, stale-result removal, mobile/focus and Axe.

Browser tests now use a unique disposable synthetic database and test-only ports18180/18181; they refuse existing servers rather than attaching to user services. Override `TELEMETRY_TEST_API_PORT`, `TELEMETRY_TEST_UI_PORT` and optionally `TELEMETRY_TEST_PYTHON` for a selected local venv. Normal application defaults remain unchanged. Tests do not modify the existing demo warehouse. Existing95% backend/85% frontend coverage gates are retained.
